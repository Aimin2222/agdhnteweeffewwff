# ライト／ダーク・Windows追従の設計
初期候補はWindowsに合わせる。明暗の好みを利用者が選べるよう、ライト／ダーク／Windowsに合わせるの3項目をヘッダー右上の固定位置に置く。基本設定の「外観」にも同じ設定への導線を置く。

## パレットと部品
- ソフトライト：背景#EEF1F4、パネル#F8FAFC、入力・補助面#E4EAF1。純白の大面積は使わない。
- ソフトダーク：背景#1B222B、パネル#252F3C、補助面#2D3A4A。純黒を背景に使わない。
- ニュートラル：プレビューの周囲#30343Aを両テーマで固定。素材の透明部分には#3C434D/#49515Dの中立マットを固定する。
- Slate Blue：主操作と選択は落ち着いた青。成功は記号✓＋正式合格、注意は△＋確認用、エラーは!＋理由、未実行は—＋未実行。
- 文字と境界色の全指定はCOLOR_TOKENS.json。色を部品ごとに直書きしない。softlineは装飾線。主要操作の境界はlineを使う。
- disabledは色だけにせず、破線と「未接続のため使用不可」等の理由を付ける。選択は太枠、チェックまたはラジオの形で分かるようにする。
- カード・警告・スライダー等の原寸部品はcomponents/のライト／ダーク各8枚。

## 状態をリセットしない切替
表示用ThemeStoreと編集ProjectModelを別にする。テーマ切替はスタイルの色・アイコン色・スクロールバー・ウィンドウ枠だけを更新する。画面やプロジェクト、カメラ、WGCソースを再生成しない。

実装側で保持するもの：選択scene_key、出力チェック、カメラ値、TargetLock、枠／FX／動作、前後長、編集中のプロジェクト、Undo/Redo、プレビュー再生位置・状態、録画ジョブとGPUリソース。テーマを変えたためにseek・再接続・再スキャン・再録画をしない。

保存例はPREFERENCES_EXAMPLE.json。既存settings.jsonへ外観設定だけをマージし、既存キーを捨てず原子的に保存する設計。保存に失敗した場合も現在のプロジェクトは維持し、警告を出す。今回、実際のsettings.jsonを変更していない。

「Windowsに合わせる」は保存値をsystemのまま保持し、起動時にOSのアプリ用テーマを解決する。OS変更通知はsystemを選択中だけ反映。手動ライト／ダークをOS側の変更で上書きしない。OSから取得できない場合はソフトライトにフォールバックする。

Windows上の実装方法は利用フレームワークに合わせる。Win32/TkでWinUIのRequestedThemeをそのまま使用できるとは限らない。非クライアント枠も含め、Windows公式のテーマ対応を参照する。[Windowsテーマ](https://learn.microsoft.com/windows/apps/desktop/modernize/apply-windows-themes)、[テーマの基本](https://learn.microsoft.com/en-us/windows/apps/develop/ui/theming)。

## 映像とサムネイルの色を守る
UIテーマは映像のLUT、ガンマ、色温度、輝度、コントラスト、合成設定を変更しない。画像にCSS filter、暗転用のopacity、テーマ色の乗算レイヤーをかけない。HDR/ICC等の映像色管理は既存の処理を維持する。

透明素材は両テーマで同じ中間色マットを使う。白・黒・発光の装飾が見えることを確認し、選択枠は素材の外側に描く。承認状態は画像へ焼き込まずラベルとして付ける。

## 今回の確認記録
- A_mainとE_mainの明暗で、主要部品のx/y/幅/高さが一致。
- Aのトリム入力、E詳細の数値入力はテーマ切替だけではリセットしないことを参照HTMLで確認。ライブプロジェクトや実動画プレイヤーの確認ではない。
- A/Eのプレビュー内側は画素一致。丸角境界外のUI背景を除く12px内側を比較した。境界外はテーマ色が変わるため対象外。
- 指定した60組の文字・主要部品の組み合わせは、通常文字4.5:1／主要部品3:1を満たす。
- 通常／選択／無効、正式合格／確認用／未実行／エラーの部品見本を両テーマに用意。
- ブラウザーのテーマ保存と起動時の反映は参照機構。Windowsネイティブ設定・通知・録画継続の実機確認は採用後に必要。

背景色だけで長時間の疲労軽減を保証しない。詳しい調査範囲と根拠はRESEARCH_JA.md。
