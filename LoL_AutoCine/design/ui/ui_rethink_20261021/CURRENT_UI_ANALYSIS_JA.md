## 現行UIの課題と設計判断
| 観察・コード上の状態 | 初心者・編集者への影響として想定されること | 今回の対応 |
|---|---|---|
| 9レイアウトを起動後に選ぶ | 制作を始める前にUI自体を選ぶ負担 | 6案は比較候補として提示。採用後の製品で6種類のレイアウト選択を必須にはしない |
| 簡単／詳細、レイアウト番号、編集ゾーン、別図鑑、旧設定が並存 | どこで何が変わるか追いにくい | Eは簡単作成とStudioの役割を定義。Aは1つの作業空間を維持 |
| ヘッダー、シーン欄、カードに作成への入口が複数ある | 「自動で探して作る」「チェック分を作る」の対象が分かりにくい | 主要CTAは仕事場ごとに1つ。対象件数と作成方式を併記 |
| 過去の9案は左右入替とカード追加が中心だったと差分報告にある | 名前が変わっても操作順がほぼ同じに見える | プリセット起点、シーン起点、ショット起点、キル前後起点等を分ける |
| 1660×940の参考画面で小さいラベル・入力欄が多い | 読み取りと狙いを付ける負担が大きい可能性 | 本文16px、補助14px、主見出し20px、標準操作40pxを基本 |
| 右カメラ欄と下の4段表示が常時領域を使う | 空データ時にも映像の余白を削る | Eでは時間軸を通常作成から外し、Studioで開く。Cでは動作編集に用途を絞る |
| 素材・詳細の一部は基本設定から別画面を開く | 映像を見ながら変更を比較しにくい | 上位2案に固定プレビュー付きの素材・詳細画面を追加 |
| 旧部品は複数テーマ前提の色指定ではない | 明暗切替で文字・境界・サムネイルの見え方がばらつく | 色トークンを役割で共有。切替時は色だけ更新する仕様 |

これはコード・資料・静止画からの設計レビュー。実利用者の操作時間、誤操作率、長時間利用の疲労は測定していない。

## 維持する機能
- リプレイの準備・読込・最近の試合、対象選手とTargetLock、試合全体スキャン、キル／アシスト／両方、プレイヤー絞り込み、出力チェック。
- 従来カメラ、固定視点＋自動構図補正、フルオートシネマ、既存10スタイル、BLUE/RED/自動、数値、Orbit／ドリー、確認済み候補と除外。
- テンプレート、参考動画、色・DOF・FX、HUD、キーフレーム、シーン別保存、コピー・貼付、順序、Undo/Redo、プロジェクト保存読込。
- 既存37バッジ、Work枠652候補、FX35点、弱／強、既存6種類の登場動作。
- GPU方針と実使用の区別、録画、ゲーム音・BGM、出力FPS・出力先・中止、診断・QA・ログ。

全設定を全画面へ展開するのではなく、日常の主経路と詳細・システム設定への導線を分ける。内部機能を削除する提案ではない。モック内の基本設定は導線のみで、実装されていない。

## 保護する状態・品質台帳
最新カタログは枠652候補のうち正式合格1、確認用651。エフェクト35点はすべて確認用。No.083 Aの合格を同名FXへ継承しない。今回UI図鑑へ原本のコピーを参照表示したが、素材制作・修正・承認を行っていない。

フルオートの候補はBLUE/RED別の明示承認を維持。候補なしの既存固定視点フォールバックとクリップ境界での選択を維持する。Fの3段階UIは既存変数を時刻に沿って整理する案で、カメラ計算の新規追加ではない。
