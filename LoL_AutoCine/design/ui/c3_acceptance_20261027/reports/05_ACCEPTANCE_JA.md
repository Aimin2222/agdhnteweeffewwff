# Codex実装版の受入準備

UI_ACCEPTANCE_CHECKLIST.jsonに、共通検査と70項目の個別導線を記録しました。**全項目NOT_RUN**。実装が届くまではPASSにしません。旧PR51の試験報告は参考証拠であり、この受入台帳へ転記しません。

実行時にビルド/コミット、元画面ID、派生ID、論理解像度、画像の実ピクセル、DPI、テーマ、選択シーン、接続状態、取得日時を記録します。各caseへ実結果と画像/ログ証拠を添付します。

原本再現、C3-P、C3-S、差分修正案は別の基準です。原本は1672×941、C3は1920×1080/1366×768。無断リサイズして比較しません。必要な原寸変換はX=1920/1672、Y=1080/941を記録し、古い手計測の不確かさ±8原画pxと、新規JSON辺±2pxを分けます。±8pxは画像忠実再現の合格を自動保証する許容ではありません。

新規C3の主要文字は指定サイズ±1pxを目安とし、フォント置換とAA差は個別記録。境界/余白/固定領域は測定、色・読みやすさの好みはPREFERENCE_REVIEW.jsonへ別記録します。好みが良くても操作欠落や状態消失をPASSにしません。

tools/compare_screens.pyは静止PNGを原寸で重畳・差分化する補助ツールです。同寸法のみ処理し、異なる場合はFAIL。ゲーム映像/時刻などの可変部分だけマスク可能で、UI枠やボタンは隠しません。出力のMAEや差分面積だけで自動合格にしません。実際のUI品質はREVIEWと個別caseの操作試験で判定します。

機能の無効表示は「操作不能ボタンなし」の例外として理由・必要条件・能力IDを記録します。ENGAGE/BESTSHOTは未実装のため、理由表示が正しくても実機能成功をPASSにしません。操作説明の合格と能力の未実装を分けてください。

実LoL、GPU、音声、MP4、DPI、クリック/キー/フォーカス/Undoはすべて実機検証が必要です。今回の補助ツール自己試験は画像処理の確認だけであり、Codex実装の受入ではありません。
