# AutoCine v5.10.19 開発実装仕様とWindows実機テスト

## 本版の前提
- ベースはCodex GPU Full統合ブランチの v5.10.15 コミット `0e8e8f65362fd10a3ab9509c3fcbb4580b72691d` からの累積差分。
- v5.10.18の全機能を維持し、音声キャプチャ、WGC、NVENC、HUD、GPUエフェクトの実装自体は置換していません。
- このビルドは **ユーザーが報告したRED/BLUE構図不具合を切り分けるテスト版** で、WindowsのReplay APIから返る回転形式は、数値計算・静止画だけでは完全には実証されません。
- xMedia参照MP4は受領していますが、この会話のPython/CaaSがClientError/InvalidArgumentErrorのため、現時点で**映像の中身を確認できていません**。分析できたような説明・参考動画再現の主張はしません。

## カメラ修正
- 通常3人称で Xを上下軸と誤認した際、水平回転がZ軸へ流れて映像が上下反転した問題に対し、問題が確認された通常3人称だけ水平=X・上下=Y・Z=0で制御する条件を追加。
- RED geo_aimで Y=200度に達し空を向いた状態を、確認済みのREDシネマと同じX/Y回転軸の経路に変更。BLUE geo_aim（良好だった10番）は変更しない。
- C-P 水平距離が4500ゲーム座標単位を超える通常3人称のTopカメラ古い読み取りを除外。キャッシュの正常値か、良好例に基づく安全な方角を使用。
- RED third_cinema と lolnam_cinema に限りキル瞬間に近づきすぎる動きを制限。良好BLUE7/9は極力維持。
- ただしカメラが本当に主役を映すかはReplay API実機テストが必要。位置が近くても向きが違う場合は別途映像認識や座標の再キャリブレーションが必要。

## UI/色合い修正
- 左の独立した「テンプレート」カードを削除。かんたん編集内にテンプレート図鑑・A/B選択を移動（A/Bは削除しない）。
- 詳細編集のカラー頁に同じ共有テンプレート選択を配置。両編集モードは同じ `var_tpl` に紐づく。
- かんたん編集に「色だけ細かく調整する」チェックボックスを追加。ONで色強度・色温度・コントラスト・彩度を数値入力/スライダーで変更。OFFで欄をたたんでも値は保持。
- 起動直後は無加工プリセットを既定にし、色補正以外のビネット/粒子/ブルーム/フラッシュも無効（全て0/カット）に。四隅が暗くなるビネットは明示的なテンプレートを選んだ時だけ反映。
- アイスブルー、ゴールド、ネオンのテンプレート色差を調整。プレビュー/Windows動画では要確認。

## 開発用ボタン1回で作るもの
- RED/BLUEを各フォルダに分類してカメラ撮影。各側 `RED_camera_review_all.mp4` / `BLUE_camera_review_all.mp4` をまとめて生成。録画失敗時は元MP4を保持。
- カメラ画像（単発）だけでなく各側 `RED_camera_3frames.jpg` / `BLUE_camera_3frames.jpg`：キル前/中/後の3時点表示。完全なキャラの画面内検出ではない。
- 従来の10種類の明るさ系の動画は維持。ユーザー報告どおり似て見えるため別系統で**実際の空間変形6種類**（crossfade/wipeleft/slideright/circleopen/pixelize/smoothup）のテスト用MP4を追加。こちらは2つの録画素材から作る比較用で無音、**現時点の製品版通常モンタージュ効果を置換していません**。
- `transition_3frames.jpg` では切替直前・瞬間・直後を見比べる。瞬間1枚だけが白飛びして同じに見える問題を回避。
- キルフレーム登場6種類のサンプル、JSONメタデータ、画像、動画を合計500MB以下の直接ZIPに分割。各ZIPにZIPを入れない。
- 最新テスト内容はオンラインJSONから取得。通信失敗時は添付のJSONで実行し、既存録画/GPU/音声処理を変えずに動く。

WindowsテストZIPとCodex差分ZIPはGitHub Releasesから各1ファイルを**直接ダウンロード**。二重ZIPは廃止。
Codex差分は基準コミットと必ず比較してレビュー。既に進んだGPU/音声/録画実装を旧コードで置き換えない。
