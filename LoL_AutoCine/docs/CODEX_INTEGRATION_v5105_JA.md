# v5.10.5 — UI統合とミラーONでの操作負荷改善

## 診断と原因

今回受領したWindows診断では、5本とも60 FPS録画/時間補正/加工、NVENC、GPU Bloom+DOFの書き出しが成功しています。加工45.1～57.5秒、時間補正2.8～3.9秒です。PC全体CPU平均81～88%はアプリ単独の値ではありません。GPU効果が成功していても、色補正・粒子・合成・形式変換とミラー簡易FXはCPUに残ります。

ユーザーはミラーONでのスライダー・カラー変更、タブ切替とスクロールが重いと回答しました。旧プレビューはUIスレッドで大きい画像の変換/縮小、Camera/FX/カラー/DOF合成、ヒストグラムとTk描画を通常16msごとに実行していました。グラフも変数更新のたび同期再描画し、テンプレート適用の連続更新で処理が重なります。受領UIには公式アイコンの取得をUIスレッドで待つ新しいプレビューボタンもありました。

## 修正

ミラーの取り込み後画像変換と合成を単一daemonワーカーへ移しました。未処理要求は最新1件へ置換し、設定・ソース・サイズの世代キーが一致する結果だけ表示します。Tk変数はUI上でTemplateへコピーし、ワーカーはTkへ一切アクセスしません。簡易FXは最大15Hz/960×540、非加工ミラーは最大30Hz、通常の録画/出力は60 FPSです。キャンセル・終了はワーカー完了を待ってUIを止めません。グラフ再描画を20msにまとめ、見えているヒストグラムだけ0.5秒間隔で間引いた画像から更新します。current_templateの不要なTk変数生成もなくしました。

キルフレームの公式画像取得とPNG生成もバックグラウンドへ移しました。表示だけをUI pumpへ送り、二重クリックによる並行ダウンロードを防ぎます。

## UI差分の安全な統合

受領patchを逆適用してUI側の正確なv5.10.4基準を復元し、現行版と3方向マージしました。衝突はjobs/kill_icons/GPUテストの5ファイル。新しいcamera_sideの既定/末尾追加、サイド基準の180度補正、新しい最大3段のキル画像/発光を採用し、smart_highlight無効時の速度非変更、短い装飾入力で動画を切らないeof_action=repeat/shortest=0、追加済みTemplateフィールドの位置互換テストを維持しました。core/effects.pyはcamera_sideの末尾1フィールドだけの変更です。

GPU係数/FPS選択、60 FPS録画/時間補正、WGC子分離・非同期ミラー、API Keep-Alive/遅延制限、従来0.35倍スロー、LoL専用音声を維持しています。
