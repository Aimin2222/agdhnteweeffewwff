# Issue #53 開発用BAT版：Windows一括QA手順

この試験版は、v5.10.31-testで使っていた**BATで従来Tkアプリを起動し、画面内の開発用一括QAを1回押す**方式に戻したものです。ソース基準はv5.10.32-test / PR #49。以前作成したIssue #53のEXEは今回の開発テストには使用しません。既存版・7案比較版・P1〜P3比較版のフォルダは上書きしないでください。

`LoL_AutoCine/START_ISSUE53_DEV_QA.bat`を起動します。従来の`START.bat`を**同じコマンド画面内**で呼び、Python 3.12環境を確認してアプリを起動します。初回は依存パッケージのセットアップにネットワークが必要な場合があります。Native LoL音声helperはZIPに同梱します。

通常のBATダブルクリックではFlashのPTS時刻修正とZoomのtmix正規化をONにします。従来処理と比較するときは、同じBATに`legacy`引数を付けて起動します。

```bat
START_ISSUE53_DEV_QA.bat legacy
```

両モードで同じリプレイ・イベント・カメラ・FX設定を使い、出力フォルダを分けてください。通常の`START.bat`と既存EXEは従来処理のままです。

## 事前確認

1. BAT版ZIPを新しい空フォルダに展開し、`LoL_AutoCine/BUILD_INFO.json` のコミットを記録する。Windowsのパス長制限を避けるため、展開先は `C:\AutoCine-I53` のような短いパスを推奨する。深い階層では展開時に「ファイルが見つからない」となることがある。
2. LoLクライアントと互換性のある `.rofl` を用意する。パッチ違いのリプレイは再生できない場合がある。
3. GPU/NVENCとゲーム音声のテストでは、NVIDIA GPUとLoLリプレイを実際に起動する。
4. 保存先に空き容量があることを確認する。一括QAは計14本のカメラ録画と追加演出を作るため、容量と時間を使う。

## 既存のワンクリックQA

LoLリプレイ再生中にアプリの**「開発用：カメラ＋Work素材一括QA・30MB ZIP」**を1回だけ押してください。未接続なら接続→10人確認→試合全体スキャンから始めます。BLUE/REDの手動各5種、固定自動・フルオート各1種、つなぎ・登場・Work素材、比較画像、診断、30MB以下の分割ZIPまで既存経路で処理します。元1080p動画と画像原本はPCに残ります。完了までLoLを終了・操作しないでください。

BATのコマンド画面はアプリ終了まで1つ残り、診断を表示します。短命のコマンド画面が繰り返し現れる症状は、実LoL一括QAで再確認してください。再発した時刻と操作を記録してください。

## 実機で順に試す項目

| 番号 | 操作 | 確認内容 |
| --- | --- | --- |
| 1 | BAT起動と終了 | 起動時例外がなく、コマンド画面が繰り返し点滅せず、終了後に余分なLoL録画プロセスが残らない |
| 2 | `.rofl` を開く | クライアントでリプレイが再生される |
| 3 | 開発用一括QAボタンを1回押す | 接続・全試合スキャン・14本のカメラ録画・Work素材検査・比較画像・30MB以下の分割ZIPが記録される |
| 4 | シーン選択とTargetLock | 選択したプレイヤー・シーンが意図どおり維持される |
| 5 | BLUE、RED各1件 | カメラの上下反転がなく、対象が画面内に収まる |
| 6 | 固定自動・フルオート各1件 | 位置、角度、距離が極端に飛ばない |
| 7 | ミラープレビュー | 表示FPSの実測値、映像の鮮明さ、FX時のカクつきを記録する |
| 8 | キルフレーム・6motion・FX | 画面と最終MP4で同じ素材・方向・時刻になる |
| 9 | Flashのキル瞬間 | キルより前のフレームが明るくならず、キル後に点灯する |
| 10 | Zoom Blur | 白飛びが減り、中心画質に過度なぼけがない |
| 11 | MP4書き出し | 1920×1080・60fps、映像・LoL音声の同期、NVENC使用ログを確認する |
| 12 | 診断収集 | `CameraQA_.../results.json`、`WorkQA/report.json`、必要時の`COLLECT_DIAGNOSTICS.bat`と元MP4を確認する |

各項目を **PASS / FAIL / REVIEW / NOT_RUN** で記録し、失敗時は時刻、選択シーン、画面画像、出力MP4、診断ログを残してください。`NOT_RUN` は合格に数えません。録画クラッシュや音声欠落は要約ログだけで判断せず、元の診断ログを確認してください。

## このビルドで未検証の範囲

開発側のFFmpeg単体フレーム試験と保存済みゲーム録画の再合成は、**開発用一括QAのライブ完走結果とは別**です。NVENCエンコードと保存済み音声のMP4合成は開発側で確認しました。この環境ではLoLクライアント起動が拒否され、実リプレイ接続、一括QA完走、LoL専用音声のライブ録音、144Hz実測、カメラ12ルールの研究案、全652素材の個別品質合格は未検証です。Flashはイベント時刻に対するFFmpeg PTS、Zoomはtmix正規化の試験実装で、正式採用は未決定です。
