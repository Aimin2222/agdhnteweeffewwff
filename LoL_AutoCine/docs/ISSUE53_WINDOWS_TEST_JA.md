# Issue #53 機能試験版：Windowsテスト手順

このZIPは従来 v5.10.32-test を基にした、別起動の試験版です。既存版・7案比較版・P1〜P3比較版のフォルダは上書きしないでください。`LoL_AutoCine_Issue53_Test.exe` を起動します。Flashの時刻修正とZoomの明るさ修正だけをこのEXEで有効にしています。通常の `START.bat` と既存EXEは従来動作のままです。

この試験EXEでも従来処理と比較できます。PowerShellで展開先へ移動し、次のコマンドで起動すると両修正をOFFにします。通常起動は両修正ONです。比較するときは同じリプレイ、シーン、出力設定を使用してください。

```powershell
$env:AUTOCINE_RESEARCH_FLASH = 'legacy'
$env:AUTOCINE_RESEARCH_ZOOM = 'legacy'
.\LoL_AutoCine_Issue53_Test.exe
```

この設定は起動したPowerShell内だけで有効です。試験EXEを通常起動し直せば修正ONに戻ります。

## 事前確認

1. ZIPを新しい空フォルダに展開し、`BUILD_INFO.json` のコミットを記録する。
2. LoLクライアントと互換性のある `.rofl` を用意する。パッチ違いのリプレイは再生できない場合がある。
3. GPU/NVENCとゲーム音声のテストでは、NVIDIA GPUとLoLリプレイを実際に起動する。
4. 保存先に空き容量があることを確認する。実録画は容量と時間を使う。

## 実機で順に試す項目

| 番号 | 操作 | 確認内容 |
| --- | --- | --- |
| 1 | EXE起動と終了 | 起動時例外がなく、終了後に余分なLoL録画プロセスが残らない |
| 2 | `.rofl` を開く | クライアントでリプレイが再生される |
| 3 | 全試合スキャン | キル・アシスト候補が時刻・BLUE/RED別に表示される |
| 4 | シーン選択とTargetLock | 選択したプレイヤー・シーンが意図どおり維持される |
| 5 | BLUE、RED各1件 | カメラの上下反転がなく、対象が画面内に収まる |
| 6 | 固定自動・フルオート各1件 | 位置、角度、距離が極端に飛ばない |
| 7 | ミラープレビュー | 表示FPSの実測値、映像の鮮明さ、FX時のカクつきを記録する |
| 8 | キルフレーム・6motion・FX | 画面と最終MP4で同じ素材・方向・時刻になる |
| 9 | Flashのキル瞬間 | キルより前のフレームが明るくならず、キル後に点灯する |
| 10 | Zoom Blur | 白飛びが減り、中心画質に過度なぼけがない |
| 11 | MP4書き出し | 1920×1080・60fps、映像・LoL音声の同期、NVENC使用ログを確認する |
| 12 | 診断収集 | `diagnostics` 内のログと出力MP4のパスを記録する |

各項目を **PASS / FAIL / REVIEW / NOT_RUN** で記録し、失敗時は時刻、選択シーン、画面画像、出力MP4、診断ログを残してください。`NOT_RUN` は合格に数えません。録画クラッシュや音声欠落は要約ログだけで判断せず、元の診断ログを確認してください。

## このビルドで未検証の範囲

開発側のFFmpeg単体フレーム試験と保存済みゲーム録画の再合成は、実リプレイ接続やライブ録画と別です。NVENCエンコードと保存済み音声のMP4合成は開発側で確認しました。LoL専用音声のライブ録音、実リプレイ接続、144Hz実測、カメラ12ルールの研究案、全652素材の個別合格は実機試験結果が得られるまで合格とは扱いません。Flashはイベント時刻に対するFFmpeg PTS、Zoomはtmix正規化の試験実装です。研究案の採用は未決定です。
