# LoL AutoCine v5.10.16 実装とWindowsテスト（開発専用）

## ベースと配布
- ベース: Codex統合 v5.10.15、コミット `0e8e8f65362fd10a3ab9509c3fcbb4580b72691d`
- 変更作業: `autocine/v5.10.16-ui-motion-qa-codex-safe`
- 「Windowsテスト用フルZIP」と「Codex統合用差分ZIP」は GitHub Actions の成功実行から別々に取得します。
- `main` と以前のCodex統合ブランチは書き換えません。
- Codex差分は元のコミットで `git apply --check` してからレビュー・適用してください。

## 実装
1. 右側の「スキャン」で未接続時にReplay API接続→プレイヤー取得→試合全体スキャンを連続実行。左側の重複接続ボタンは廃止。
2. DOFを円形／従来の上下ぼかしのラジオボタンに変更。選択したモードの設定だけを表示。右側の図は概念図（真の奥行き測定ではありません）。
3. 右側スクロールを高速化し、コンボボックスの展開時のホイール抑制は維持。
4. カメラ用語を「回り込み」「近づく量」など一般的な名称に変更。内部キーや設定値は維持。
5. 37枚の既存キルフレームPNGは変更せず、一部の表示名をスキンテーマ風へ変更。旧表示名は読み取り互換保持。
6. キルフレームの登場方法を追加：瞬時、左から、右から、下から、上から、ポップ。FFmpegのオーバーレイ座標のみ変化させ、既存音声処理は不変更。
7. カメラ切替時に、前回の成功した視点に対して非ピッチ軸だけ180度近く跳ねるAPI読み取りを抑制。**Windows映像での上下反転解消は未検証。**
8. 開発用ボタン：RED/BLUE各4カメラ＝8本の短いクリップを録画し、その完成素材から10種類のつなぎ演出を生成。各結果をJSONへ保存。ユーザー操作でのみ開始し、中止できます。

## Windowsでしてほしいテスト
- [ ] リプレイ再生後、右側の「スキャン」1回で接続、10人取得、試合全体スキャンが終了するか。
- [ ] プレイヤー・イベント表示を切り替えても、再スキャンしないか。
- [ ] 円形 DOF を選ぶと円形だけ、従来方式を選ぶと上下ぼかしだけの設定が見えるか。数値が保持されるか。
- [ ] スクロールが改善され、プルダウン展開中に背後の右パネルが誤スクロールしないか。
- [ ] 37種類のフレームが表示され、スキンテーマ名と実際の絵柄に違和感がないか。
- [ ] 6種類の登場モーションを各1シーンで書き出し、方向や表示時間がおかしくないか。
- [ ] **重要**：BLUE / REDの通常3人称、シネマ3人称、FPS、Lolnamシネマをそれぞれ2回以上選び、地面と空が上下反転しないか。
- [ ] 「開発用：カメラ8本＋つなぎ演出10種類を自動テスト」で8本＋10種類が生成され、エラーログがないか。
- [ ] 1080p/60fps、NVIDIA NVENC（対応PC）、LoLゲーム音、HUD、TargetLock、録画後ミラー復帰が従来どおりか。
- [ ] `results.json`、該当するMP4、`AutoCine_Diagnostics.zip`を共有できるか。

## 自動テストと制約
CIはLinux/Xvfb＋FFmpegを使用し、pytest、構文チェック、差分パッチ適用確認、ZIP CRCを検証します。
Windows実機LoL・GPUドライバー・音声デバイス・カメラの画作りはCIでは確定できません。
現時点でアップロード済みの動画/診断ZIPはChatGPT側ファイル実行環境エラーで直接読み直せていません。
