## 2. プロジェクトの理念・絶対条件

**LoLのリプレイを選ぶ → 対象プレイヤーを固定 → キル／アシストを検出 → 1クリックでカメラ演出・色・FX・LoL音声付きの高品質な横型モンタージュを出力**できるWindowsアプリ。初心者にも直感的な「かんたん編集」と、DaVinci Resolve／Lolnamを参考にした「詳細編集」を**両立**。ユーザーは継続して日本語での説明とUI日本語化を希望。

- **横型1920×1080・16:9中心**。標準出力は1080p/60fps。144Hzは内部カメラ・ミラー・必要に応じたFPS指定の話であり、**縦型Shorts出力は不要／追加しない**。
- 既存の正常機能を勝手に削除・全面刷新しない。変更する場合は後方互換・テスト必須。
- 配布：**Windows実機用フル版ZIP + Codex統合用の変更差分ZIP**を毎回2つ。別々の開発ブランチの更新ファイルを無造作に上書きしない。
- ユーザーはテストを実行してログ・MP4・スクショを送り、こちらがログ解析→修正→ZIPの反復を希望。
- GPU/NVENCを優先し、失敗すれば安全にCPU経路へフォールバック。GPU使用率だけで「GPUエフェクト実行」と判定しない。
- **ゲーム音のみ**：デスクトップ全体の録音に戻さない。LoLプロセス専用のWindows Process Loopback方式が実機で成功している。
- 人間が操作するのは基本1クリック。詳細編集では自由に編集／保存できる。
- 既存`TargetLock`（プレイヤーの固定）、三人称カメラの座標系と視点を破壊しない。
- 色付きのプレビューなのにMP4が白黒になる過去不具合を再発させない。
- チェックの見た目は「■に×」ではなく分かりやすい ✓。英語機能名は可能な限り日本語へ、設定名も正確に。
- ユーザーが望むHUD：**体力バーは表示、キャラクター／プレイヤー名は非表示**。体力バーと名前の可否はLoL自身の設定に依存する部分があり、完全自動化を確認せず断言しない。

## 4. 重大な過去バグと守るべき修正

### 音声
- 過去のProcess Loopbackでネイティブエラー／`0x80004001 GetMixFormat`／`captureClient`未宣言等。
- Windowsネイティブ音声ヘルパー `tools/native_audio/lol_audio_helper.cpp` を利用。Windows Process Loopback APIを使い**LoLの対象PIDと子プロセスの音だけ**を収録。ビルド関連：`ENSURE_CPP_BUILD_TOOLS.bat`, `BUILD_AUDIO_HELPER.bat`, `START.bat`。
- `GetMixFormat`を使わずPCM形式を指定し、capture client取得などを修正した結果、実機で `LoL音声OK: 13.98s / offset 0.055s` 等の録音成功が確認された。
- 全デスクトップ音を録るフォールバックはプライバシー・要件面で不適切。音声が失敗した場合は記録し、音のない成功を「音声あり」と偽らない。
- LoL録音WAV→AAC音声のMP4結合を継続。音声ストリームがあることとA/V同期の良さは別なので、実機で音ズレ確認。

### FFmpeg／GPU
- 過去の`hwdownload,format=yuv420p`が `Invalid output format yuv420p for hwframe download` で2クリップ失敗 → v5.7.8で問題のCUDA downloadパスを外し、安定CPUフィルター＋NVENCエンコードへ変更。
- プレビューはカラーなのに出力が白黒になった不具合を修正。カラー処理・BT.709等の互換を再確認する。
- `Focus Blur`／DOFが重い問題→低解像度でBlurして戻す処理等。
- CPU高負荷：以前は約9秒クリップを約68〜85秒で処理、平均CPU約70〜80%。一部OpenCLフィルターはFFmpegに存在せずCPU実行。GPUエフェクトの完了を過大申告しない。
- `core/effects.py`、`core/gpu_pipeline.py`、`core/jobs.py` の結線・既存効果を壊さない。

### UI／カメラ
- Tkinter `RuntimeError: main thread is not in main loop`：ワーカースレッドから`tk.Variable.get()`等を呼ばない。UIメインスレッドで値を取得してデータにしてからワーカーへ渡す。
- 過去`CurveEditor`のCanvas width/height多重指定クラッシュ。kwargsに`setdefault`を使う。
- 過去UIルート変数`r`を行番号`r,c=divmod(...)`で上書きし`int has no attribute tk` → 行列変数名を分離。
- 「チェックしたシーンだけ作成」クリック直後の応答なし・終了コード `-805306369`：v5.8.4で正しい処理のログ追跡・二重起動防止・UI描画負荷低減が入りユーザー実機で成功。
- 過去「動きをプレビュー」がグラフを更新するだけだった→v5.9.4でLoLカメラ実際の移動へ接続。
- Camera Replay API最大約60〜122ms待ち／以前最大0.73秒時刻ずれ。v5.9.4で内部時計の取りこぼしを抑え、診断でずれ約0.04〜0.10秒になったが、**見た目のガクつきは残る**。
- 青／赤サイドで「キャラクターの後ろ」が変わる。三人称斜め後ろは**空から見下ろす高さ**で、地面すれすれの横アングルではない。0／90／180／270度Orbitでターゲットを見失わない。対象中心の視線・座標系を維持。以前、気に入った三人称斜め後ろのカメラをユーザーが明確に採用した。

## 5. 次のv5.9.9 — 必須実装（ユーザーが再三指定）

**完成扱いにするには全項目が実コードとテストで裏付けられること。**

1. **キルアイコン装飾テンプレート4種**：シンプル／シネマ・ゴールド／ネオン・ブルー／インパクト・レッド。かんたん編集でワンクリック選択。詳細編集で位置・大きさ・色・表示時間・場面ごとのON/OFF・保存。右側キルフィードを装飾。キル瞬間のイベントと同期。元のLoL HUDは変えず、装飾を映像へ後合成する方式が好ましい。ゲーム公式の画像を無許諾でコピーせず、オリジナル装飾で開始。現開発ブランチ`core/kill_icons.py`にはPillowで透明PNGバッジ作成しFFmpeg`overlay`を行う基礎コードがあるが、**実機テスト・全オプションの実装は未確認**。
2. **スマート構図補正**：選択キャラクターを見失わない。手前の木／壁／地形で遮られる場合にカメラ距離・高さ・角度で軽減。単純なReplay API座標だけでは厳密な遮蔽検出はできないので、映像解析／視点候補の採点など具体的に検証。勝手に俯瞰へ不自然に飛ばさない。
3. **Replay APIカメラのガクつき改善**：高頻度のHTTP呼び出しによる遅延・時計補間・ターゲット追従更新を見直し、カメラモーションが滑らかになるか実機検証。ミラー144Hz希望だが、Replay APIポーリング自体を144Hzで叩きすぎない。一定間隔でサンプル取得し、可能なら補間／バッファ／速度制限。TargetLockの原理は維持。
4. **キル前後の連動演出**：キル前→寄り→キル瞬間の短い発光／Blur→短いスロー→自然に戻す。ズーム・発光・スローモーションのタイミングを同じイベント時計で同期させる。短いスローが音声同期／クリップ長／次のシーンを破壊しない。
5. **スマートモンタージュ自動構成**：複数キルから見せ場を選定、順序と構成に意味を持たせ、場面転換・テンポを自動設定。時刻順連結しかできない仕組みから段階的に発展。ユーザーが詳細編集で並べた順序は無断変更しない。
6. **詳細編集との統合**：上記の自動結果を手動で編集・保存・Undo/Redo・再読込。簡単編集／詳細編集の切替でも状態維持。初期OFFの新エフェクトは既存挙動に影響させない。

**特に注意**：この6項目は以前から「実装する予定」と案内されているが、ZIPを作る実行環境が`ClientError`で失敗し**v5.9.9配布済みではない**。2026-10-09時点、GitHubには**部分実装のみ**。未検証の動作を「完成」「テスト全部通過」と書かない。

## 8. 開発・テスト・配布のルール

1. 最新ZIP／GitHubブランチとドキュメントの整合を確認。Python`py_compile`、pytest等で回帰テスト。Windows実機専用のReplay API/NVENC/Process Loopbackは**未テストならそう明記**。
2. 高速化を主張する場合はFFmpegログと実測処理時間を比較。GPU使用率だけで実際のエフェクト実行を証明しない。
3. 1クリップ通常→4種類のキルアイコン→1シーンのカメラとタイミング→2シーンとモンタージュ→詳細編集保存／Undo／再読込→音声・カラー・同期の順に確認。
4. 必須の自動テスト例：
   - キル時刻とキルアイコンの表示時間の一致
   - 複数キルが近接した際のアイコンの重なり・表示維持
   - `off`スタイルの既存映像と音声への無影響
   - シーン設定で`inherit`と個別スタイルが正しく優先される
   - キーフレームの単調時刻・有限値・端点の滑らかさ
   - Warp/Slow時の音声長・映像長・イベント同期
   - 右／左サイドのカメラ後方方向と0/90/180/270度のTargetLock
   - GPU可／不可、FFmpeg失敗時に正常フォールバック
   - ワーカースレッドからTk UI変数を読まない
   - 操作前プレビューと実際の出力で補正・色・カメラが一致
5. 実機テスト指示は番号付きで短く説明し、`COLLECT_DIAGNOSTICS.bat`または`diagnostics/latest_diagnostics.zip`の提出を依頼。落ちたらログを送ってもらう。
6. 完成したら**①WindowsフルZIP ②Codex差分ZIP**。差分はGitパッチ＋適用説明・変更一覧を入れる。既存GPU／音声の変更を古いファイルで上書きしない。
7. 出力は日本語、ファイル名は文字化け防止にASCII中心、仕様書はUTF-8 Markdown。
8. システムや実行環境が使えない場合は、その旨を正直に伝える。**ファイルが実際に作成できていないのにsandboxリンクを作らない**。
