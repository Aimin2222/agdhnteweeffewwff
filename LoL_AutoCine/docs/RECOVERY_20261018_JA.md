## 現在のWindows環境

隔離Python 3.12.14とrequirements／pytestを導入し、pip checkに成功。GTX 1070 Ti、VRAM 8GB、ドライバー582.78を認識した。通常の`py`ランチャーとPATH上のFFmpegは未検出。Codexの同梱Pythonで行った検証を、スタンドアロンPythonの導入確認と混同しない。

GUIの起動・イベント処理・終了と、合成赤映像＋合成音声の1秒1920×1080/60fps書出しに成功。NVENCとlibx264をそれぞれ確認。既定imageio FFmpeg 7.1にはprogram_openclがなく、GPU FXはCPUへフォールバックした。NVENC成功はGPU FX成功ではない。

Native Audio Helper実行ファイルとVisual Studio Build Toolsは未検出。LoLのみの実音声、Replay API実接続、WGC録画、実対象のTargetLock、実機構図、長時間同期は未検証。

初回の広いテスト実行では、未統合のWindowsテスト修正に加え、長い一時パス、symlink作成権限、複数Tk rootの問題を検出した。過去ログを保持し、再検証結果は `RECOVERY_TEST_RESULTS_20261018.json` に分けて記録する。収集漏れやスキップを合格に読み替えない。

最終照合では、全864件に対する結果を回収した。初回全件の835件の結果と、その後の完全なモジュール／ケース再実行を照合した集計で、862成功・2失敗・error/skip 0。単一の全件実行が全成功したという意味ではない。残る2件はsymlink作成時のWinError 1314で検査本体へ進めず、未合格のまま。新旧の検証記録をJSONへ保持した。GUIをケース別プロセスに分けて不足29件を回収したが、アプリ側のTcl寿命問題の根治とは扱わない。

PATHにFFmpegがなくスキップしていた3つの実動画バッジ検査は、アプリと同じFFmpeg選択関数を使うように変更して再実行し、3件とも成功。バッジ画像や合成処理本体は変更していない。検証環境の固定版は `requirements-recovery-20261018.txt` に保存した。

## ユーザーが準備するもの

1. スタンドアロンのPython 3.12と`py`ランチャー。復旧版の短い専用フォルダーで `SETUP_DEV_ENV.bat -3.12` を実行し、`.venv`へ依存関係を入れる。既存の設定や録画へ旧ZIPを上書きしない。
2. LoLクライアントと、現在のクライアントで再生できる同じリプレイ。同じ対象・同じキル時刻を比較に使う。
3. LoL専用録音を使う場合は付属 `BUILD_AUDIO_HELPER.bat` のC++構築手順を実施する。復旧作業では管理者インストールを実行していない。
4. GPU FXの実行確認には付属の検証済みOpenCL FFmpeg導入経路を使う。`START_GPU.bat` は大容量ダウンロードを開始し得る。今回は実行していない。PATH上の既存対応FFmpegがある場合だけ `START_LOCAL_GPU.bat` を使う。
5. 合成テスト中はLoLを閉じる。実機QAでは `START_GPU.bat` 等で起動し、開発用の全カメラテストを同一シーンで行う。通常出力は1080p60、送信用QAだけ540p60・各30MB以下。
6. 全part ZIP、results.json、診断をローカルに保持する。個人パス・プレイヤー情報・録画を公開Gitへコミットしない。
