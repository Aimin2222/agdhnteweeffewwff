# カメラ・Work素材の一括QAと今回の診断（2026-10-20）

## 受領した実機テストの事実

`CameraQA_20261020_130341_521328` の4分割ZIPと診断ZIPを確認した。カメラ10/10本、モンタージュ3種、既存バッジの登場6種、空間切替6種は生成され、記録上の失敗は0。送信用動画は960×540・60fps、各ZIP30MB以下。10本とも従来の手動カメラで、固定自動・フルオートの実映像QAではない。比較JPEGに明白な上下反転は見られないが、追従品質や主役の見やすさは静止画だけで合格にしない。

診断内の書き出し61処理は終了コード0でNVENCを利用した。ただしGPUエフェクト確認は61件すべて`false`で、うち12件には`ffmpeg_missing_program_opencl`の理由がある。ミラーはGTX 1070 TiのOpenCL経路と、非対応効果のCPUフォールバックの双方を実行している。NVENC、ミラーGPU、最終出力のGPU効果は別経路である。

10本の録画は出力フレームのうち新規取得フレームが62〜68%で、中央値は約39fps相当だった。WGC側は16msの更新間隔を指定しているのに、追加の`1/60秒`判定が合法的な約16ms間隔の到着も捨てていた。この二重判定を外し、WGC子プロセスが5秒ごとに実取得fpsを記録するよう変更した。原因の一部として根拠はあるが、LoL側の描画fps・録画負荷もありうるため、改善結果は次回のWindows録画で確認する。

同じ実録画を入力にした追加のオフライン検査では、Work素材998 PNGのSHA・RGBA・寸法に不一致0。652フレーム候補、35演出案、311旧レイヤーを確認し、35演出の合成と8種類の枠配置サンプルが例外なく処理された。正式合格はNo.083 Aの1件のまま。ミラーGPUの640×360効果処理はウォームアップ後の中央値22.82ms。ただしこの数値にはWGC取得・Tk画像転送・LoL再生は入らない。

受領済みの実録画を入力にして新しいWorkQAを再実行し、998画像の破損・ハッシュ不一致0、35演出の合成失敗0、6登場動作の描画失敗0を確認した。GPUミラー試験はGTX 1070 TiでOpenCLを使用。ウォームアップ後中央値31.66msは一例であり、実際のミラーfpsやユーザー体感を示す値ではない。

「開発用：カメラ＋Work素材一括QA・30MB ZIP」を1回押すと、接続→全試合スキャン→BLUE/RED各5カメラの手動基準撮影＋固定自動・フルオート各1本（計14本）→つなぎ・既存登場・空間切替動画→比較画像→Work素材998件の整合性→652候補の図鑑シート→35演出の合成→GPUミラーの実録画サンプル計測→診断収集→各30MB以下のZIPまで実行する。録画の元ファイルと画像原本は保持する。WorkQAの`report.json`とJPEGシートが分割ZIPにも入る。処理途中の結果は`results.json`へ段階的に保存する。フルオート候補に実機QA合格が未登録なら、安全な固定視点へのフォールバックとして記録される。

このボタンは全652候補を動画で品質合格させるものではない。未合格画像は図鑑で「仮素材」と表示し、明示的に選ぶと合成出力に使える。肖像穴未検証の候補は仮の丸位置へ本物のチャンピオンアイコンを前面配置する。原本や品質台帳は変更せず、将来同じ素材IDへ検証済み位置を追加すれば自動的に正式配置へ切り替わる。

ミラーは「余白なく拡大」を初期ONとした。16:9映像を横長のプレビュー枠いっぱいに表示するため上下が一部切れる。「全体表示」に戻すにはチェックを外す。完成MP4は1920×1080・60fpsのままで、トリミングはしない。
