# LoL AutoCine v5.9.9 — キル装飾＋安定カメラ＋スマートモンタージュ

## 原則

v5.9.8をベースに追加実装。**既存のTargetLock、Windows Process Loopback LoL専用音声、NVENC優先/CPUフォールバック、HUD、かんたん編集/詳細編集、Undo/Redo/シーンJSON、横型1080pを維持**。縦型Shorts機能は追加しない。

## v5.9.9の変更

1. **キルアイコン装飾：4種類**：かんたん編集で「シンプル／シネマ・ゴールド／ネオン・ブルー／インパクト・レッド」を選ぶ。初期値「なし」なら旧版と同じ。HUDそのものではなくMP4に透過PNGバッジを重ね、キルイベントの時刻で表示。ゲーム側の素材をコピーしない独自アイコン。
2. **詳細編集**：表示位置（右上/右下/左上/左下）、倍率（0.5〜1.8）、表示秒数（0.45〜4秒）、不透明度（0.25〜1.0）を編集。設定保存、再起動後の復元、シーン別スタイル上書き（「全体を引き継ぐ」も可能）。Undo/Redo対応のシーンJSONと両立。
3. **スマート構図補正**：スマート自動編集時に有効化。三人称追走の最低距離・仰角を安全寄りに設定し、ゲーム地形で遮られにくい高さ/距離を優先。これは**地形を直接検出した結果ではない**ため、必ずしも完全に遮蔽を回避できるわけではない。
4. **Replay API安定化**：HTTP送信間隔を実際のAPI待機時間に応じて調整。playback時間の再照会を抑え、スローモーション用playbackコマンドも間隔を制限。TargetLock補間は維持。
5. **キル前後の連動演出**：v5.9.8の5点キーフレーム＋キル瞬間アクセントを維持し、同じReplay時刻の速度・FOV・ズーム変化と組み合わせる。スローモーションはReplay APIの再生速度を変える方式であり、FFmpegで勝手に映像の長さを再度変える方式ではない。
6. **スマートモンタージュ**：通常は候補を全部利用。候補が12シーンを超えたときはマルチキル・時間的な重複を考慮して最大12シーンに絞り、導入からクライマックスへ並べる。手動順序がある場合は尊重。選ばれた各シーンの出力、最後のモンタージュに既存の切替（自動設定時の暗転）を利用。

## かんたん編集（最短）

1. `START.bat` → LoLリプレイへ接続 → プレイヤー固定。
2. 「キルアイコン装飾」で好きなテンプレートを選択（不要なら「なし」）。
3. 自動カメラ演出タイプを選び「✨ スマート自動編集」を押す。
4. 出力したMP4の右側キル装飾、カメラ構図、キル瞬間の寄り/発光/スロー、LoL音声を確認。

## 詳細編集

「詳細編集」の出力エリアに「キルアイコン装飾（全シーン共通）」設定がある。位置・倍率・秒数・濃さを個別調整。「シーンごとの色・エフェクト」でシーン別の装飾スタイルを変更できる。プロジェクトJSONを保存し再読込。自動モンタージュの順序は手動保存済みの順序を優先する。

## Windows実機で依頼したいテスト

1. **旧版回帰**：「なし」設定の通常自動作成で1本。色があり1080pでLoL音声が残ること。
2. **キルアイコン4種**：各1本。右上に出ること、キルの瞬間から約1.55秒後に消えること。ネオン/シネマの光、インパクトの小さい動き、音声に異常がないこと。
3. **詳細編集の調整**：位置を右下、倍率1.2、表示2.5秒、不透明度0.6にし保存→再起動→再読込。同じ設定で動画が出ること。
4. **構図補正**：以前障害物に隠れたシーンをv5.9.8と同じ設定で比較。キャラクターが見える割合、画角の自然さを確認。
5. **カメラ**：連続したキル2本以上でReplay APIのガクつきが改善したか。診断の`最大API待ち(ms)`を控える。
6. **モンタージュ**：3〜5キルで順序とつなぎ目、戦闘のテンポ、音ズレがないこと。12件超の場合だけ自動で見せ場を絞ること。手動並べ替え後は順序が保持されること。
7. **詳細編集**：キーフレーム・シーン別色FX・Undo/Redo・JSON保存/復元が壊れていないこと。
8. **エンコード**：NVENCで出力できるか、CPU高負荷やクラッシュが増えていないか、Windowsヘルパーの音声録音が動くか。
9. `COLLECT_DIAGNOSTICS.bat` を実行して診断ZIPを送る。可能なら問題が分かる10秒程度のMP4も添える。

## 制限・未確認

- Linuxの自動テストではWindows/LoL API/GTX 1070 Ti本体の挙動を再現できない。GPUのエフェクト本体はCPU処理のままのものが多く、すべてGPUにしたわけではない。
- Replay APIで地形の深度／視線遮蔽データを取得しているわけではない。高さ・距離の安全マージンによる**遮蔽低減**であり、キャラクターを100%見失わない保証はない。
- ユーザーがアップした参考動画の音楽・画像・キルアートをコピーしたものではない。類似技法の独自実装。
- Windows実機テスト結果はユーザーの出力MP4・診断ログで確認すること。
