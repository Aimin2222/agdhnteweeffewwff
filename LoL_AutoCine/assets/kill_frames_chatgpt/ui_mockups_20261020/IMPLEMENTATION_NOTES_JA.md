# LoL AutoCine — Windows新UIモックの実装引継ぎ

制作対象は画面構成の比較用モック画像。カメラ・フレーム・エフェクトの素材制作と、本体の実装作業は含まない。モック内のフレーム・エフェクトの小さな画像は配置を示すイメージであり、制作中の素材の修正・追加や品質承認を意味しない。

## 共通の画面設計

- 1920×1080、16:9を設計基準とする。納品PNGの実寸はMANIFEST.jsonに記録し、設計上の寸法と区別する。
- 白いパネル、ライトグレーの作業面、青の選択・操作アクセント、濃い文字色。表示文字は日本語を基本とする。
- 中央のミラープレビューは独立した固定ペインとする。シーン一覧・図鑑・インスペクタ側だけをスクロールできる構造。ライブラリやウィザードでもプレビューを残す。
- ミラープレビューは実装時に既存のミラー映像へ接続する。モック内のゲーム映像は生成による視覚イメージで、実LoL映像や実動作の証拠ではない。
- タイムラインも固定ドックとする。高さ変更は可能としても、通常操作でプレビューを覆わない。
- 「簡単編集」と「詳細編集」は同じ設定データを共有する表示モード。簡単編集への切替で詳細値を消去・初期化しない。
- カード選択とスライダーを主操作にし、スライダーの値は併設の入力欄からも変更できるようにする。チェックボックスはラベル全体をクリック可能にする。
- 日本語の主要ラベルは実装時18px前後を目安とし、タイムコード等の補助文字は14px以上を目安に検証する。生成画像内のフォントサイズや字形をそのまま実装仕様とはしない。

## 機能の導線

| 既存機能・操作 | 画面上の導線 | 実装時の扱い |
|---|---|---|
| 試合全体スキャン | シーン一覧上部の大きいボタン | 既存のスキャン処理へ接続 |
| 検出シーン | 時刻・種別・サムネイル・大きいチェック欄 | 選択結果をプレビューとタイムラインへ反映 |
| カメラ | ショットのカード＋詳細インスペクタ | 既存の各カメラ設定を維持 |
| キルフレーム | 図鑑・検索・カテゴリ・画像カード | 素材の存在と品質の承認状態を混同しない |
| エフェクト | 専用一覧・画像カード・強度入力 | フレームと別に選択・調整できる導線 |
| 書き出し | 右上の青い主ボタン | 出力設定を表示して既存出力処理へ接続 |
| 出力設定 | 右側の要約カード＋設定を開く | 解像度・fps・形式など既存設定を維持 |
| GPU・音声 | 常設の「基本設定」 | GPU方式や音声設定を削除しない |
| HUD・TargetLock | 基本設定＋編集インスペクタ | 既存制御を維持。画面モード切替で状態を失わない |
| 37キルバッジ | 基本設定内の専用項目 | 新規フレーム図鑑に統合して既存37件を消さない |

全機能をすべての画面へ展開する必要はないが、既存機能への導線は維持する。本体を実装する際は現行設定項目の全リストと照合し、省略項目を別の設定画面へ明示的に配置する。このモックだけで全既存機能の実装・接続が完了したとは扱わない。

## 案の比較

| 案 | 納品画面 | 主な配置差 | 想定される使い方 |
|---|---|---|---|
| 3：ハイブリッド固定プレビュー | 通常・詳細の2枚 | 同じ作業空間で右側の設定密度を切替 | 初心者の通常作業から詳細調整へ自然に進む |
| 6：ライブラリ＋編集分離 | ライブラリ・編集の2枚 | 素材を探す画面とシーンを組む画面を分離。両方に固定プレビュー | フレームやエフェクトを画像で比較しながら選ぶ |
| 5：ステップウィザード | メイン1枚 | 上部の4ステップと右側の案内 | 初回の利用手順を明確にする |
| 2：動画編集ソフト標準 | メイン1枚 | 素材・プレビュー・インスペクタの3列と大きなタイムライン | 編集に慣れた利用者の連続操作 |
| 4：ドック型 | メイン1枚 | カメラ・素材・音声・出力を独立ドックで整理 | 表示領域を好みに合わせたい利用者 |
| 1：ワンクリックホーム | メイン1枚 | スキャンとおすすめ設定の主操作を目立たせる | 最小操作で見どころを出力したい利用者 |

案3を初期画面の候補として推奨。通常と詳細でプレビュー・シーン・タイムラインの位置関係を維持しやすく、画面を覚え直す負担を抑えられる。案6の図鑑構成は、案3から開く素材選択ペインにも応用できる。

## 固定表示・スクロール・縮小時

外側ウィンドウを縦に長いページとして実装せず、ヘッダ／中央ワークスペース／タイムラインのグリッドに分ける。各リスト・設定ペインだけにスクロールを与える。モーダルの素材図鑑でプレビュー全体を覆わず、横のペインとして開く。

小さいウィンドウでは、右インスペクタまたは左ライブラリをタブ式に畳み、中央プレビューを優先して残す。文字を極端に小さくして1920pxの配置を縮小しない。案4にはレイアウトを初期状態へ戻す操作を設ける。

## 納品と保留事項

PNGは案と画面が分かる英数字ファイル名で整理。PROMPTS.jsonに画像生成の共通条件と画面別の指示を保存する。生成は組み込み画像生成を使用し、有料APIへの切替は行わない。

モックの採用案、実際の最小ウィンドウ寸法、現行GUIフレームワークへのマッピング、キーボード操作、アクセシビリティ、スクロール・リサイズ時の実挙動は、本体側の実装段階で確認する。画像の静止配置だけで固定表示の挙動を検証済みとは扱わない。
